# Flow

This repository contains Flow's static product website. The repository name and current sitemap host still use the legacy ZimLive name; DNS, domain ownership, and redirects are outside this code change.

Flow is a product of **O’Riley Foundation**, its parent company. The intended product architecture has native Android and iOS clients, a browser-based web app, and shared backend services. The linked repository roles, shared color palette, and current capability statements are maintained in the [Flow product system](https://github.com/elvkun/ryvo-hardened/blob/main/docs/PRODUCT_SYSTEM.md).

## Current implementation status

The related [`ryvo-hardened`](https://github.com/elvkun/ryvo-hardened) repository contains the Android app, iOS introduction, browser app, and API source. The browser app uses Firebase Auth and Firestore for accounts, profiles, private listing drafts, reports, and published listing discovery when a Firebase project is configured. Android service screens use local demonstration data; iOS does not yet connect to shared accounts or services. Payments, identity verification, messaging, and AI services are not available.

This site presents product direction and interface concepts. Example feeds, profiles, counts, wallets, and service screens are illustrative UI; they do not indicate active users, verified accounts, processed payments, live synchronization, or deployed services. Update this disclosure when those capabilities are implemented and verified.

## Website

The site uses semantic `index.html`, a standalone stylesheet at [`styles/site.css`](styles/site.css), and native ES modules for navigation, consent preferences, and lightweight reveal motion. It has no analytics or advertising integration in the reviewed source. The cookie-choice preference is stored in local storage for up to 180 days; the web account session may use essential browser storage when sign-in is requested. Scroll reveals use the browser's `IntersectionObserver` once per element and animate only opacity and position; there are no continuous loops or added image/font downloads. Motion is omitted for reduced-motion preferences, and content remains visible without JavaScript. Serve the repository root with any static web server; root-relative asset paths expect the site to be hosted at the domain root. UI design tokens and guidance are in [`DESIGN.md`](DESIGN.md).

The sitemap is [`sitemap.xml`](sitemap.xml), and [`robots.txt`](robots.txt) points crawlers to it at the current apex host `zimlive.app`. Fragment links are in-page navigation and are not separate sitemap entries. The parent company website is [O’Riley Foundation](https://www.orileyplatforms.com/).

The public platform section contains an inline Firebase email sign-in, account creation, email verification, and password recovery experience. Account creation requires an unchecked acknowledgment linking to the [Flow Privacy Policy](https://zimlive.app/privacy-policy.html); this is separate from cookie choices and does not represent blanket consent to processing. The cookie panel offers “Accept all cookies” and “Essentials only”; no optional analytics or advertising technology is active in the reviewed site source. Users can reopen choices from the footer. The policy is an interim engineering disclosure and identifies owner-provided details still required before a compliance claim. The page stays on `zimlive.app`; it does not send credentials to a separate app site. Firebase public web configuration, email/password Authentication, and the `zimlive.app` authorized-domain entry are configured. Account controls remain disabled because the privacy/data-handling gate is false and deployment of this source to the live host has not been confirmed. Profile editing, private listing drafts, reports, and published-listing discovery are in the separate [Flow browser workspace](https://zimlive-app-offocial-webiste.vercel.app/) and require that app's Firebase configuration and deployed Firestore rules. If both sites use the same Firebase Authentication project and provider, users can use the same credentials, but must sign in separately on each domain; sessions and Firestore data are not shared automatically. Follow [Firebase web account setup](docs/FIREBASE_WEB_ACCOUNT_SETUP.md) before enabling the account panel. Store links open Google Play and Apple App Store search pages because verified Flow listing URLs have not been provided. The social preview and favicon are local SVG assets; interface artwork is illustrative rather than live product data.

The page's Content Security Policy allows same-origin app code plus the pinned Firebase Web SDK CDN and the specific Firebase Authentication endpoints used by email/password sign-in, while disallowing form submission, objects, and framing. The production Firebase web app config is present and `zimlive.app` is authorized in Firebase Authentication; account fields remain disabled until privacy readiness is approved and this source is confirmed deployed to the intended host. [`vercel.json`](vercel.json) applies matching response headers, including `frame-ancestors 'none'`, for Vercel deployments. If you deploy this static site elsewhere, configure equivalent headers at that host; `frame-ancestors` is ignored inside a meta policy.

## Security maintenance

GitHub CodeQL analyzes the website JavaScript on pushes, pull requests, and weekly. Dependabot checks GitHub Actions dependencies weekly. This site has no package manager dependencies to audit. The Vercel response-header configuration adds framing protection and browser security headers; review code-scanning alerts and keep these workflows enabled.
